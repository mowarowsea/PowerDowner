# PowerDowner

URL を貼るだけで、直リンク・CivitAI・ワンクリックホスター (rapidgator, katfile, turbobit など) を
自動で振り分けてダウンロードする自宅用の Web 司令塔。

```
URL 投入 → Router → aria2 (直リンク / CivitAI)         … 分割・再開・無限リトライ
                  → JDownloader 2 (ホスター、ローカル API) … プラグイン任せ。GUI 無し (headless) で常駐する
                  → ブラウザ引き継ぎ (Edge を Playwright で操作) … JD2 が扱えない人間判定 (Cloudflare Turnstile など) は
                                                              人間が実ブラウザで通し、始まったダウンロードを aria2 が引き継ぐ
```

katfile のように無料ダウンロードが Cloudflare Turnstile で守られているサイトは、JD2 では「外部 (有料) ソルバーが必要」として
ブロックされる。その場合は自動でブラウザ引き継ぎに回る。`config.json` の `browser.hosts` に書いたドメインは最初からブラウザへ行く。

- Node.js 24 以上だけあれば動く。SQLite は Node 内蔵のものを使う。
- aria2c.exe、JRE、JDownloader.jar は `tools/` に「置くだけ」。インストール不要。
- ユーザーはデータ切り分け用の簡易モデル (名前 + 既定フォルダ)。パスワードなし。
- **起動するのは PowerDowner 1 個だけ。** aria2 も JDownloader も PowerDowner が起動し、終了時に片付ける。
- **「もう持っているか」は自分で覚えない。** 蔵書カタログ [pinax](http://127.0.0.1:3838/) の棚に聞く ([下記](#もう持っているかは棚に聞く))。

将来の構想 (DryEyes 連携、ntfy 通知、ミラーの優先度選択、LocalLauncher への統合) と、
そのためにここを壊すなという前提は [docs/ROADMAP.md](docs/ROADMAP.md) にまとめてある。

## アップローダの台帳

**どのアップローダを使うか、どの順で試すかは画面の「アップローダ」で決める。**
実績 (成功 / 失敗 / 人間待ちの回数、最後に成功した日時) が業者ごとに貯まるので、
それを見て「使用する」を外したり、優先度を並べ替えたりする。

- 「使用する」を外した業者は、DryEyes から来ても手で貼っても**ジョブにならない**。
  画面にはトーストで理由が出る (ログにも残る)。
- ミラーのうち一部だけが無効なら、**その URL だけ落として残りで試す**。
  1 つ外した途端に、その巻ごと落ちてこなくなる、ということにはならない。
- 別名ドメインは 1 業者にまとまっている (frdl.io / frdl.hk / frdl.by)。
  片方だけ外して裏口が残る、ということもない。
- 業者が新しいドメインに移った場合は、**使用する**状態・優先度は最後で自動的に台帳へ足す。
  勝手に止まるより、一度落としてから人間が判断するほうがよい。
- サイトの仕様が変わって通らなくなったら、直すのではなくここを外す。それで運用が続く。

台帳の正は DB (`hosters` テーブル)。`config.json` の `mirrors.priority` は
**初回の並び順を決めるだけ**で、以降に書き換えても効かない。

### 実績の初期値 (2026-09-08〜09 に実機で確認)

| ホスター | 経路 | 状況 |
|---|---|---|
| dailyuploads | JD2 | 完走を確認 |
| uploady | ブラウザ | JD2 は hCaptcha で不可。ドライバの自動操作で完走を確認 |
| frdl | ブラウザ | frdl.hk へリダイレクト。hCaptcha 1 回で直リンクまで到達。無料は 10 分間隔。人間の仕事はチェック 1 回だけ (下記) |
| katfile | **自動不可** | Turnstile が CDP を検出して弾く。下記の手動リレーで運用する |
| mexa.sh | JD2 | まず JD2 に任せる。詰まったら自動でブラウザへ。サイトが Cloudflare 522 を返す時期があり、その場合は 10 分ごとに自動で試し直す |
| turbobit | ブラウザ | Vue SPA。Regular Download から進む |
| rapidgator | **自動不可** | katfile と同じく Turnstile が描画されない (枠だけ出て中身が空)。人間が見ても押すチェックが無いので、待っても通らない。優先度は katfile の手前まで下げてある |

JD2 が CAPTCHA の種類 (hCaptcha / reCAPTCHA / Turnstile) で詰まった場合と、
「wrong captcha」「Blocked by Cloudflare」で進まなくなった場合は、自動でブラウザ経路へ切り替わる。

**JD2 の中では hCaptcha と Turnstile の扱いが違う** (2026-09-10 に JD2 のログで確認):

- hCaptcha / reCAPTCHA は `BrowserSolver` が受け持つ。JD2 が `127.0.0.1` に一時的な
  ページを立てて既定ブラウザで開き、人間に解かせる (`Solver: [BrowserSolver, CaptchaAPISolver]`)。
- Cloudflare Turnstile は**候補がゼロ** (`No solver available!` → `SkipException: BLOCK_HOSTER`)。
  JD2 の Turnstile 対応は有料 API ソルバー前提で、無料枠には出口が無い。
  turbobit / katfile / rapidgator が揃って `SKIPPED|CAPTCHA` になるのはこれが理由で、
  プラグイン自体は 3 つとも無料モードに対応していて、最後の Turnstile まで進んでいる。

いずれにせよ headless 運用では JD2 に CAPTCHA を出す画面が無いので、**種類を問わず**ブラウザ経路へ回る
(`jd2.headless` を `false` にすると GUI 起動になり、hCaptcha は JD2 の BrowserSolver で解ける)。

## セットアップ

```bash
npm install
powershell -ExecutionPolicy Bypass -File scripts\fetch-tools.ps1
```

`fetch-tools.ps1` が `tools/aria2/aria2c.exe`、`tools/jre/`、`tools/jd2/JDownloader.jar` を用意し、
JD2 の Deprecated API (127.0.0.1:3128) を有効化する設定も書く。

必要なら `config.example.json` を `config.json` にコピーして編集する (ポート、aria2 の並列数、JD2 に回すドメインなど)。

## 起動

```bash
npm run dev               # PowerDowner → http://localhost:3939/
```

JD2 は PowerDowner が勝手に起動する (`jd2.autoStart`)。既に動いていればそれを引き継ぐので、
`scripts\start-jd2.cmd` で先に立ち上げてあっても構わない。LocalLauncher から回すなら `start.bat`。

1. 「ユーザー / 設定」からユーザーを作り、既定フォルダを絶対パスで登録する
2. URL を貼って「追加」。ジョブ単位で保存先を上書きすることもできる。
   作者・作品名を紐づけて落としたいなら「作品として登録する」を開く (下記)
3. 人間判定が要るジョブは「人間待ち」になり、Windows 通知で呼ばれる。実ブラウザでチェックを押せば残りは自動

### JD2 の起動まわりの設定 (`config.json` の `jd2`)

| キー | 既定 | 意味 |
|---|---|---|
| `autoStart` | `true` | API が応答しなければ PowerDowner が JD2 を起動する。落ちたら 15 秒周期で起こし直す |
| `headless` | `true` | GUI 無しで起動する。窓もトレイもクリップボード監視もバブル通知も出ない |
| `stopOnExit` | `true` | PowerDowner の終了時に JD2 も落とす (`autoStart` が `true` のときだけ) |
| `dir` / `javaExe` | `tools/jd2` / `tools/jre/bin/java.exe` | 置き場所 |
| `startTimeoutSec` | `240` | 起動待ちの上限。初回は自動アップデートで数分かかる |

`headless` の代償は **JD2 が CAPTCHA ダイアログを出せなくなること**だけ。PowerDowner は
それを検知して自前のブラウザ経路へ回すので、運用上は「リンクをコピーしても JD2 が
ポップアップしてこなくなる」効果の方が大きい。

手で起動・停止したいときは:

```bash
scripts\start-jd2-headless.cmd   # 画面には何も出ない
scripts\stop-jd2.cmd             # 窓もトレイも無いので、止めるにはこれを使う
```

CivitAI のログイン必須モデルは、設定画面で API キー (CivitAI のアカウント設定で発行) を保存しておくと落とせる。

## 運用メモ

- JD2 の初回起動は自動アップデートに 90 秒ほどかかる。`jd2.startTimeoutSec` (既定 240 秒) はそのための余裕
- JD2 の headless は `-Djava.awt.headless=true` だけで足りる。`Application.isHeadless()` が
  `GraphicsEnvironment.isHeadless()` を見ているので、GUI もトレイもクリップボード監視も丸ごと起動しなくなる
- headless の JD2 は起動時に `IllegalStateException: No Console Available!` を吐くが**正常**。
  画面も端末も無いので JD2 の対話コンソール UI が初期化できないだけで、API は問題なく動く。
  ログには意味の分かる 1 行に置き換えて出している (`JD2_BENIGN`)
- **Windows では PowerDowner に SIGTERM が届かない** (`taskkill /F` でしか落ちない)。つまり
  ランチャーに止められると終了処理が走らず、画面の無い JD2 が取り残される。対策は 2 つ入れてある:
  起動時に「応答しない JD2」を PID で片付ける (`killStale`) のと、既に動いている JD2 の引き継ぎ。
  ランチャー側にも `scripts\stop-jd2.cmd` を `stop_command` として登録しておくとより確実
- JD2 は起動するだけで 500 行近くログを吐く。`JD2_NOTEWORTHY` に当たる行だけを拾っている
- JD2 のローカル API は GET + URL エンコード JSON で呼ぶ。応答は `{"data": ...}` で包まれ、`status` 文字列は日本語ローカライズ済みなので判定には使わない
- PowerDowner を強制終了しても aria2c は生き残る。次回起動時に応答があればそのプロセスを引き継ぎ、進行中のダウンロードも続きから追跡する
- `.ps1` は UTF-8 BOM 付きで保存する。BOM 無しだと PowerShell 5.1 が日本語を CP932 として読んで構文エラーになる
- `page.evaluate()` に**関数を渡してはいけない**。tsx (esbuild) が keepNames の `__name` ヘルパーを埋め込み、
  ブラウザ側で `ReferenceError: __name is not defined` になる。ブラウザ内で動かすコードは文字列で渡す
- `form.id` は `<input name="id">` に影が差して要素を返す。id 属性が欲しいときは `getAttribute('id')` を使う
- `document.hidden` / `visibilityState` の偽装は**人間判定に嫌われる**。Cloudflare Turnstile が
  「Verification failed」で弾く。自前でカウントダウンを止めるサイト (uploady) だけに効かせること
  (`browser.keepAwakeHosts`)。他のサイトは Chromium の起動フラグだけで足りる
- hCaptcha は `recaptchacompat` モードだと `textarea[name="g-recaptcha-response"]` も作る。
  reCAPTCHA と誤認しないよう、hCaptcha の痕跡を先に見る
- **アップローダのドメインは 1 つではない**。ページ本体、アセット CDN、直リンクがそれぞれ別ドメインになる
  (frdl.io → frdl.hk、アセットは cdn.freedl.ink、直リンクは e21.urleecher.com)。
  「同一ドメインかどうか」で何かを判定すると必ず壊れる。ファイル名や拡張子など中身で判定すること
- Playwright の `route('**/*')` で全通信を横取りすると、それ自体が自動化の signature になり
  Cloudflare Turnstile が「Verification failed」で弾く。横取りは落としたい URL だけに絞る
- **1 回のクリックでは進まないサイトがある**。dailyuploads は Free Download を押しても
  広告のポップアンダーが開くだけで本来の遷移をしない (人間も 3〜4 回押すことになる)。
  ポップアップが開いただけのクリックは「押した回数」に数えず、間を置かずに押し直す
  (`clickPersistently`)。ここを数え違えると、広告に吸われた 3 回で人間待ちに落ちる。
  ポップアップを閉じたあとは操作中のページを `bringToFront()` で前面に戻す
- **広告が操作を邪魔するサイトは `browser.adGuardHosts` に入れる** (既定は dailyuploads)。
  効くのは 3 つ。**他所へ向かう `window.open` を握り潰す** (ポップアンダーは閉じるより開かせない。
  自分のサイトへの `window.open` は通す)、**開いてしまったポップアップは行き先が分かった瞬間に閉じる**、
  **メインフレームを他所へ飛ばす遷移を止める**。
  ただし `keepAwakeHosts` と同じで、ページ読み込み前のスクリプト差し込みは自動化の痕跡になる。
  **Turnstile が厳しいサイト (katfile, rapidgator) には入れないこと**
- **潰した `window.open` は console 経由でポップアップ 1 回として数える** (`__pd_popup_blocked`)。
  数えないと、広告に吸われたクリックが `clickPersistently` から見て「進んだクリック」になる
- **ポップアップを時間で見張って閉じてはいけない**。1.5 秒待つ間ずっと画面を奪われる。
  `framenavigated` で行き先が決まった瞬間に判定する。ただし**新しいタブでダウンロードを
  始めるサイトがある**ので、ファイルへ向かう URL と download 検知済みのタブは閉じない
  (閉じると download イベントの受け皿ごと消える)
- **待ち時間の最中に広告がページごと他所へ飛ばしてくる** (dailyuploads の「Create Download Link」で
  60 秒数えている間に起きる)。**飛ばされてから戻ったのでは意味がない** — カウントダウンが
  振り出しに戻り、また飛ばされて永久に終わらない。`page.route` で**メインフレームの遷移そのものを
  止める** (`blocksNavigation`)。止められた遷移は現在のページを壊さない (`net::ERR_ABORTED`) ので、
  秒数は進み続ける。見るのはメインフレームだけで、サブリソースと iframe には触らない
- **`route.abort()` の既定は `net::ERR_FAILED`**。これでページ遷移を止めると、Chromium が
  **その広告 URL のまま「このページに到達できません」を描き**、待っていたページごと失われる
  (実機で踏んだ: `jf.lozengybind.cfd` のエラーページに着地した)。
  **`abort('aborted')` = `net::ERR_ABORTED` だけが遷移を「無かったこと」にできる**。
  サブリソースを落とす側 (AD_HOSTS) も同じ理由で `'aborted'` に揃えてある
- それでも広告のページに着地してしまったら `backToJob` で戻す。ただしこれは保険で、
  **戻るとカウントダウンは振り出しに戻る**。本筋はあくまで遷移を止めること。
  戻る動作を繰り返すと広告と往復し続けるので、3 回で諦める
- **止めてはいけない遷移が 2 つある**。**別ドメインの直リンク**(ファイル名で見分ける。止めると
  ダウンロードそのものが始まらない) と、**`about:blank` / `blob:` / `data:`**
  (ダウンロードの受け皿になっていることがある)
- **ページ側の `route` で `continue()` を呼んではいけない**。ページの route はコンテキストの
  route より優先され、`continue()` するとそこで打ち止めになって AD_HOSTS の遮断をすり抜ける。
  自分で処理しないときは **`fallback()`** で次へ渡す
- **メインフレームの遷移先を無条件に「同一サイト」へ足さない**。広告へ飛ばされた先を足すと、
  その広告ドメインが開くポップアップまで自分のサイト扱いになり、閉じられなくなる
- 新しい広告配信網に当たったら `config.json` の `browser.adHosts` に足す。
  何が素通りしているかは `/api/jobs/:id/dump` の「遮断」欄と `data/debug` の HTML で見る
- **カウントダウン中の送信ボタンは disabled のことがある** (dailyuploads の
  「Create Download Link」)。押せる状態になるまで待つ。空押しは試行回数を減らすだけで進まない。
  残り秒数の表示が `<span>32</span>` のような数字だけの要素でないサイト向けに、
  「Seconds remaining: 32」を本文から読む経路も用意してある (`COUNTDOWN_TEXT_RE`)
- **ブラウザ内コードに正規表現を直接書かない**。`SNAPSHOT_JS` はテンプレートリテラルなので
  `\s` と書くと `s` になり、静かにマッチしなくなる。TS 側で書いた正規表現の `source` を
  `JSON.stringify` して埋め込む
- **`op=download2` のフォームは 1 ページに複数ある**。frdl は 3 つ持っている
  (1 つ目は有料枠、2 つ目が無料枠、3 つ目は隠れたモーダル)。先頭のフォームを掴むと、
  そこには押せるボタンが無いので「ダウンロードボタンが見つかりません」で手動に落ちる。
  **押せるボタンを持っているフォームを選ぶ** (`pickSubmit`)。フォームの外にボタンを置く作りもあるので、
  どのフォームにも無ければ文書全体から文言と id で探す
- **人間判定は「見えているウィジェット」だけ待つ** (`pendingChallenge`)。frdl は 1 歩目のページから
  hCaptcha を DOM に置いたまま隠している。DOM にあるだけで人間を呼ぶと、押すものが画面に無いのに
  「あなたの番」と出て、そのうえ本来自動で押せるボタンまで人間任せになる
- **人間判定はカウントダウンより先に出す**。サイトが 60 秒数えている間にチェックを押してもらえば、
  人間の待ちとサイトの待ちが重なって実質ゼロになる。順番を逆にすると、カウントダウンが終わってから
  「あなたの番」と言うことになり、待ち時間が足し算になる
- **最終ページには押すボタンが無いことがある**。frdl の直リンクページは `op=download2` の
  フォームの中に `<a class="btn">Download Now</a>` を置くだけで、送信ボタンが存在しない。
  「フォームがある = 送信して進む」と決め打ちすると、押すものを探して 5 回空回りして手動に落ちる。
  **押せるボタンが無ければ直リンクを取りに行く**
- **ファイル名は経路によって区切りが変わる**。frdl はページ URL が `Goblin_Slayer_Manga_v15.rar.html`、
  直リンクが `Goblin Slayer Manga v15.rar` (空白)。そのまま比べると別物になり、本物の直リンクを
  見送ってしまう。比較は区切りを落としてから (`normName`)。英数字以外を全部落とすと日本語名が
  空文字になって「何にでも一致」するので、落とすのは区切り記号だけにする
- **同じボタンが状態によって文言を変える**。frdl の `#downloadbtnfree` は
  `NORMAL DOWNLOAD` → (押す) → `Almost Ready to Download` (disabled + 60 秒) → `Start Download NOW` と化け、
  **もう一度同じボタンを押すと** フォームが送信される。文言のどれかだけを見ていると途中で見失う
  (`FREE_TEXT_RE` / `SUBMIT_TEXT_RE` / `TRIGGER_ID_RE` の 3 つで拾う)

## 自動操作できないサイト (katfile) — 手動リレー

katfile の Cloudflare Turnstile は **Playwright では通せない**。ページ読み込み時に
`console.log('%c%d', 'font-size:0;color:transparent', ...)` を全コンソールメソッドで実行する
デバッガ検出が走り、CDP 接続が露見する。CDP は Playwright の動作に必須なので設定では消せない。

放置している間は Turnstile はきれいなままで、チェックを押した瞬間に「Verification failed」になる。
自動操作をどれだけ目立たなくしても (可視状態の偽装を外す、通信の横取りをやめる、初期化スクリプトを
やめる、待ち受けを軽くする) 結果は変わらなかった。

**運用方法**: 普段のブラウザで katfile を開き、チェックとカウントダウンを済ませて最終ページまで進む。
ダウンロードボタンのリンクをコピーして PowerDowner に貼る。あとは aria2 が分割・再開付きで落とす。
ブラウザに直接落とさせるより、この方が「途切れない」という要件に合う。

## ジョブ一覧の見え方

行にはファイル名の下にホスト名 (`katfile.biz` など) とエンジンのチップ (aria2 / JD2 / ブラウザ) が出る。
ファビコンは `/api/favicon?host=` がサーバー側で取ってきて `data/favicons/` に貯める。
外部のファビコン API は使わない (どのアップローダを使っているかを他所に渡さないため)。
取れなかったサイトは頭文字のバッジ画像を生成して返すので、一覧に穴は空かない。

### ミラー候補の内訳 (「候補 n/m」)

同じ巻が複数のアップローダに上がっている時、**同時並行では落とさない。上から順に 1 か所ずつ**試し、
失敗して初めて次へ移る。`Job` は 1 ファイル 1 レコードで、ミラーはあくまで
**駄目だった時の代わり**だから (docs/ROADMAP.md 4 章)。

今どこを試していて何が残っているかは、ジョブ行の **「候補 n/m」** を押すと開く。

- 試して駄目だった候補は**失敗の理由つき**で残る (`meta.tried`)。
- 今の 1 件はジョブと同じ状態 (DL中 / 人間待ち / サイト制限待ち…) で出る。
- 残りは**順番待ち**として、実際に試す順で並ぶ (`meta.mirrors`)。並びは台帳の優先度どおり。
- 同時 DL 上限で足踏みした候補は失敗ではないので、**末尾の順番待ちへ回る**。時間で空けばまた回ってくる。
- 台帳で「使用しない」に倒した後も、**既に候補に入っている分はそのまま試す**ので「除外」と付けて出す。
- URL はリンクになっているので、自動で通らないものは手で開いて落とせる。

候補はジョブの途中でも増える。DryEyes が別サイトで同じ巻を見つけると合流し、
失敗が確定していたジョブでも `queued` に戻って続きから試す。

## 落ちた後の整理 (フォルダ分けとリネーム)

完了した瞬間に、保存先の中で作品ごとに分けて名前を揃える。

```
{保存先}/[{著者}] {作品名}/[{著者}] {作品名} 第{nn}巻.{拡張子}
                            [{著者}] {作品名} 第{nn}-{nn}巻.{拡張子}   ← 範囲もの
```

- 巻数は **2 桁 0 埋め**。3 桁以上はそのまま伸びる (`第200巻`)
- 著者が分からなければ `[] ` は付けず、作品名だけにする
- 作品名・巻数は**投入時に読んでジョブに焼いた解釈**を正とし、無ければ投入メタ、それも無ければ元のファイル名から読む
- **巻数を読めなかったものは名前を変えない。** 作品フォルダには入れる。読めないまま
  `第01巻` と決め打ちすると、棚と手元が食い違って後から直しようがなくなる
- 「第12話」で来たものを「第12巻」に書き換えない (単位はそのまま保つ)
- **分割書庫の連番は残す** (`... 第03巻.part2.rar`)。均すと part1 と同じ名前になって
  片方が消え、`.r00` 系はベース名が `.rar` と揃わなくなって解凍できない
- **同じ巻をもう一度落としたら上書きせず連番を付ける** (`... 第03巻 (2).rar`)。
  同じ巻でも中身が違う (画質違い・修正版) ことがあるので、捨てるのは人が決める
- JD2 がパッケージ名のフォルダを掘っていたら引き上げ、空になったフォルダは片付ける
- `\ / : * ? " < > |` は全角に倒す。末尾のピリオドと空白、予約名 (CON, NUL) も直す。
  NAS の長いパスに収まらない時は作品名を削り、それでも駄目ならフォルダを掘るのをやめる
- **整理に失敗しても完了は完了。** 落ちた名前のままそこに置いてログに残す。
  ファイルはもう手元にあるので、名前が揃わないことより「落ちたのに失敗と言われる」ほうが困る

組み立てと読み戻しは `src/naming.ts` に対で閉じてある。**テンプレートを設定にしていない**のは、
自由に書けるようにすると棚 (pinax) が読み戻せない名前を人間が書けてしまい、
手元にあるのに「持っていない」と判断して二重に落とすため。切りたい時は `config.json` で:

| キー | 既定 | 意味 |
|---|---|---|
| `rename.enabled` | `true` | `false` なら落ちてきた名前のまま置く |
| `rename.folder` | `true` | `false` ならフォルダを掘らず、リネームだけする |

## 作品として登録する (DryEyes を通さない)

完結した古い作品や 1 冊だけのシリーズのために、**PowerDowner だけで作者・作品名を紐づけて落とせる。**
監視を作るほどではないものに DryEyes を通さなくてよい。

追加欄の「作品として登録する」を開き、URL と一緒に**作品名** (必須)、**著者** (任意)、**巻数** (任意) を入れる。
通る道は DryEyes からの `items` と同じなので、所持の判定・ミラー・リネームの扱いは投入元で変わらない。

| 巻数欄 | URL 欄の解釈 | 使いどころ |
|---|---|---|
| 書いた (`3` / `1-7`) | 貼った URL 全部が**同じ 1 ファイルのミラー**。上から順に 1 か所ずつ試す | 1 冊だけの作品、同じ巻が複数のアップローダにある時 |
| 空欄 | **1 行 1 巻**。巻数は URL のファイル名から読む (`..._v03.rar.html` → 3 巻) | 完結作品の全巻をまとめて貼る時 |

- 作品名を入れた投入は**巻の解釈がジョブに焼かれる**ので、後から DryEyes が同じ巻を見つけても二度落とさない。
  逆に、棚に既にある巻を貼るとその場でスキップされ、理由がトーストに出る
- 落ち終わると `[著者] 作品名/[著者] 作品名 第nn巻.拡張子` に整理される (「落ちた後の整理」と同じ)
- URL からも巻数を読めなかったものは、**名前を変えずにそのまま置く**。作品フォルダには入る
- 送信後も**作品名と著者は欄に残る** (同じ作品の別巻を続けて入れるため)。巻数だけ消える
- 作品名が空欄なら、今までどおり 1 行 1 ジョブの素の投入になる (同じ巻かどうかの判定にも参加しない)

ジョブの投入元は `manual` と出るので、DryEyes 由来と見分けられる。

## もう持っているかは棚に聞く

**PowerDowner は取得済みの台帳を持たない。** 「この巻もう持ってる?」の答えを持っているのは
蔵書カタログ [pinax](http://127.0.0.1:3838/) で、投入のたびにそこへ聞く。

```
DryEyes ──▶ POST /api/jobs ──▶ PowerDowner ──┬─▶ 落としている最中か? … 手元の jobs
                                             └─▶ もう持っているか?   … pinax の棚 (POST /api/own)
```

かつては自分で `items` 表 (取得済み台帳) を持っていた。捨てたのは、**台帳がダウンロードの
記録であって棚の姿ではない**から — 手で NAS に置いたもの、落とす前から持っていたもの、
消したものが映らない。しかも台帳は「持っている」と言い切る場所なので、
**間違った行が 1 つあるだけでその巻は永久に落ちてこなかった**。
経緯は [docs/ROADMAP.md の 2.5](docs/ROADMAP.md) に書いてある。

pinax は台帳ではなく**ファイルそのもの**を正にして、棚を毎回読む。だから
**落としたファイルをここで管理しなくてよい。**

### 棚を見ても分からないことが 2 つある

どちらも「まだファイルが無い」ので、棚に聞いても「持っていない」としか返らない。
そこは手元の `jobs` を見る:

| | 見るもの | なぜ |
|---|---|---|
| 今落としている最中 | `queued`〜`waiting_*` のジョブ | 別サイトから同じ巻が来たらミラーとして合流させる |
| 落とし終わった直後 | `done` のジョブ | 棚のスキャンは 3 時間おき。**載るまでの隙間を埋める** |

ジョブが `failed` / `canceled` なら判定に参加しない。
**落とし直したい時はジョブを消せばよい** — 台帳の頃のように、消し忘れた行が
その巻を永久に止めることはもう無い。

### 棚に聞けない時は落とす

pinax が止まっていても、答えが返らなくても、**投入そのものは通る**。その時は
「持っていない」に倒して落とす。黙って持っていることにすると、その巻は二度と
落ちてこない — **もう一度落ちる方が被害が小さい** (pinax 側も、巻数を読めない
問い合わせを同じ理由で「持っていない」と答える)。

落とし直しても手元のものは潰れない。同じ名前のファイルがあれば
`... 第03巻 (2).rar` と連番を付けて置く (どちらを捨てるかは人が決める)。

### 設定

`config.json` の `pinax`:

| キー | 既定 | 意味 |
|---|---|---|
| `baseUrl` | `http://127.0.0.1:3838` | 空にすると聞きに行かない (= 判定なしで全部落とす) |
| `token` | 空 | pinax 側の `apiToken` と同じ値。向こうが空なら不要 |
| `timeoutMs` | `5000` | **短くしすぎない。** ここで諦めると持っている巻をもう一度落とす |

聞けなかった時はログに理由が出る (`[pinax] 所持を聞けませんでした …`)。
読み方が食い違った時も残すので、二重取得が始まったらまずログを見る。

## 状態

`queued → resolving → downloading ⇄ waiting_human / waiting_site → done / failed / canceled`

- `waiting_human`: ブラウザで人間判定のチェックを待っている (GUI 起動の JD2 なら CAPTCHA 入力待ちも含む)。
  Windows 通知で呼ばれる。headless では JD2 発の人間待ちは起きず、全部ブラウザ経路に回る
- `waiting_site`: サイトの無料ダウンロード間隔にかかっている。時刻が来たら自動で再開する
- `failed` と `canceled` は「再試行」で `queued` に戻る
- ブラウザから引き継いだ直リンクを aria2 が拒否された場合、再試行するとブラウザ自身が保存する (`meta.browserDirect`)

## ブラウザ引き継ぎの流れ

人間の仕事は「人間判定のチェックを押す」だけ。それ以外はドライバ (`src/drivers/xfs.ts`) が進める。

1. Edge が専用プロファイル (`data/browser-profile`) で開く。表示言語は英語に固定 (文言解析を 1 言語に絞るため)
2. ドライバが Free Download ボタンを押し、サイトのカウントダウンを待ち、ダウンロードフォームを送信する。
   ボタンが `disabled` や非表示になっている間はカウントダウン中とみなして待つ。
   裏タブでもタイマーが進むよう `--disable-background-timer-throttling` 等を付けて起動する
3. Turnstile / reCAPTCHA / hCaptcha があれば、まず 8 秒は自動通過を待つ。通らなければ画面下のバナーが橙色になり、
   Windows 通知で人間を呼ぶ。チェックを押せば残りは自動で進む
4. ブラウザがファイルを落とし始めた瞬間に URL と Cookie を取り、ブラウザ側は止めて aria2 に渡す (単一接続)
5. 別サイトなら `browser.maxConcurrent` (既定 3) まで並行して進める。
   同じサイトは 1 件ずつ (無料枠は同時ダウンロードを弾かれるため)。待たされているジョブには理由を出す

偽ボタン対策として遮断するのは **広告配信網 (`AD_HOSTS`) と他所のドメインの iframe** だけ。別サイトのポップアップは自動で閉じる。
自動操作できないページは手動モードに落ち、HTML とスクリーンショットを `data/debug/` に残す。

当初は「同一サイト以外のサブリソースを全部遮断」していたが、これは**間違いだった**。アップローダは自前の JS を
別ドメインの CDN から配る (frdl.hk → cdn.freedl.ink)。それを止めるとボタンの `onclick` が未定義になり、
ページは表示されるのに何を押しても無反応になる。偽ボタンは他所の iframe に出るので、そこだけ塞げば足りる。

ページが動かないときは `POST /api/jobs/<id>/dump` を叩く。HTML とスクリーンショットを `data/debug/` に落とし、
**遮断した要求の一覧**を返す。原因は大抵ここに出る。

```bash
curl -s -X POST http://localhost:3939/api/jobs/<id>/dump
```

落ちた HTML には、そのままドライバの目を当てられる。サイトへは一切触らずに
「どのボタンを押すつもりか」「人間を呼ぶつもりか」だけを見る:

```bash
node --import tsx scripts/probe-dump.mts data/debug/<id>-<時刻>.html
```

サイト側の「次のダウンロードまで N 分」制限を検出すると `waiting_site` になり、時刻が来たら自動で再開する。
待ち時刻は再起動をまたいでも保持される。

ページが 5xx を返した場合 (Cloudflare 522 など、サイトのオリジンが落ちている) も `waiting_site` にして
10 分後に自分で試し直す。人間を呼んでもどうにもならないため。6 回試して駄目なら失敗にする。
